ClassScout NYC Design System

The single reference for how ClassScout looks, speaks, and behaves — for designers, developers, and decision makers. ClassScout is a parent-first trust product: every element below exists to help a busy NYC parent decide faster and trust what they see.

DesignersUse the tokens, components, and do/don't rules verbatim. Compose screens from the components — don't redraw them.
DevelopersTokens live in styles.css → tokens/. Components in components/ (React, inline-styled, token-driven). The live click-through is ui_kits/classscout-web/index.html.
Decision makersThe principles and trust system below are the product strategy: specific, source-backed, honest about uncertainty. If a screen violates them, it isn't ready.

Principles

Theme: calm civic warmth — local, useful, caring, credible. Never a toy app, coupon site, SaaS dashboard, or overhyped AI product.

PrincipleWhat it means in the UI
Trust before clevernessEvery badge has an operational definition. No jokes in system states. No "verified" without a verification process.
Parent-first, not category-firstSearch starts from parent intent: age, place, date, budget — not taxonomy browsing.
Make uncertainty visible"Estimated from $45 — confirm with provider", "Last checked 2 July 2026", "Age not confirmed". Never hidden in footers.
Every listing answers five thingsAge · location · time · cost · source/freshness. A card missing one shows its "not confirmed" state instead.
Mobile is for finding, tablet for comparing, desktop for planningSame product logic everywhere; layout, navigation, and density adapt per breakpoint.
Scout is a guide, not an authority"May fit" + reasons + what to confirm. Never "best", "guaranteed", "safe", "AI verified".

Brand

One name, always: ClassScout NYC. Never "Class Scout NY", "ClassScout NY", or other mixes. The pin mark and wordmark are real assets in assets/ — never redraw them.

On dark backgrounds (navy footer, dark bands) always use the light variant assets/logo-pin-light.png; the standard mark is for oat/white surfaces. Sage #94A390 and clay #C98973 come from the mascot and are illustration accents only — never actions or semantics. Logo currently exists as PNG only; request vector source from the team.

Color

Bluestone — a cool NYC-civic palette from the city's own materials: bluestone-blue that acts, park green that confirms, burnt amber that flags estimates, brick red reserved for errors, and a marigold spark for warmth. Cool oat paper, not cream. Warm, readable, low-anxiety.

Voice & copy

Calm, practical, transparent, local, adult-facing. Precision beats promise — specific claims are what make parents trust the product.

Say
  • "Estimated price shown for planning."
  • "Last checked 2 July 2026."
  • "This may fit because it is indoor and listed for ages 5–8."
  • "Good for children who enjoy hands-on building."
  • "Schedule may change. Please confirm with the provider."
  • "No child name required."
Never
  • "Guaranteed safe." / "Fully verified."
  • "Perfect for every child!"
  • "AI-powered magic!"
  • "The best activity in NYC."
  • "Cheap" / "Only $25"
  • Jokes in loading or error states
ContentRule
Listing titleClear activity name ("Kids Robotics Workshop"), never promotional. Provider name always separate.
SummaryOne sentence, 100–160 chars: [format] for [age/interest] in [context], useful for [parent benefit].
Price"Free" · "Estimated from $25" · "Price not confirmed" — status is always explicit.
Schedule"This Saturday" · "Drop-in available" · "Schedule not confirmed" — exact vs estimated is always distinguished.
Source"Source: provider website" · "Last checked: 2 July 2026" · weak source → "Source not confirmed. Please verify details before attending."

Trust system

Nine labels, each with an operational meaning. Use a badge only when its condition is true; unknowns get the amber "not confirmed" labels, never silence.

LabelMeaning
Official sourceProvider, venue, school, city, or official event page
Public sourcePublic directory, event feed, or mapped business data
Provider claimedProvider completed the claim/update flow
Recently checkedChecked within the freshness window (events 7d · this-week 3–5d · camps 14d · classes 30d · venues 60–90d)
Price / schedule estimateUseful for planning, not guaranteed
Age / source not confirmedField inferred or missing — shown, never omitted
Reported outdatedA user flagged possible stale information

Public copy is explainable ("High confidence: recently checked from provider source") — never numeric scores, never "AI verified", "safe", or "approved".

Core controls

Buttons (one primary per screen), pill filter chips (always reversible), save and compare toggles, labelled fields. All targets ≥44px, all focus rings visible.

Labels are sentence case. Save is never hidden in an overflow menu. Selected chips turn solid teal; active-filter rows use the removable variant with ×.

Search & filters

The homepage behaves like a tool: five parent-intent fields, one primary action, Scout as the secondary path, and a trust line underneath. Quick-start cards match real parent situations.

Full filter set (age, location, date, price, type, indoor/outdoor, booking, source confidence) lives in FilterSheet — bottom sheet on mobile, 264px rail on desktop. Results always show active filters as removable chips: "Showing: Ages 5–8 · Brooklyn · This weekend".

Listing card

The most important component. It must answer: what is it, who is it for, where, when, what does it cost, how reliable is the information, and what's the next step.

Do
  • Real listing/provider imagery only; no image → honest placeholder
  • Age and source states always present
  • Price and freshness in the decision row
  • Summary ≤160 characters
Don't
  • Generic child stock photos
  • Cards without age state — use "Age not confirmed"
  • "Verified" badges without verification
  • Price uncertainty buried in footers

Detail page blocks

A detail page is a parent briefing, in this order: parent summary → key facts → why it may fit → what to confirm → source block → report path. On mobile the facts table stacks.

Scout AI

A guided discovery assistant. Every recommendation explains why it may fit, what it's based on, what's uncertain, and what to confirm — and links out. The privacy note ("Do not enter a child's full name") ships with the entry card.

System states

States communicate product quality. Loading is serious and skeletal; empty states name the search and offer recovery; errors keep a route forward. Never jokes, never dead ends.

Navigation

Desktop: one row — six task links max + "Ask Scout" CTA; secondary items (About, How trust works, legal) behind the hamburger. Mobile: exactly five bottom tabs — Search · This Week · Saved · Scout · Account. Navigation always preserves search state.

Map

The map answers "is this reachable?" — it is never the only path (an accessible list always exists). Mobile has separate list/map modes; tablet landscape and desktop use a synced split view. Few pin colours, on purpose.

Pins: teal standard · green free · navy saved · muted approximate ("Approximate area" when the exact address is unknown) · count clusters · selected = larger + navy ring. Engine recommendation: MapLibre + OSM tiles (or Mapbox). Location permission is optional and requested only on "Near me".

Accessibility — WCAG 2.2 AA

Parents use this one-handed, outdoors, carrying a child, under time pressure. Accessibility is product quality, not compliance.

RequirementHow the system delivers it
Keyboard access + visible focusEvery control uses the shared 2px teal focus ring (.cs-focusable)
Tap targets ≥44px--tap-target enforced in buttons, inputs, nav tabs, save controls
No hover-only interactionsHover only darkens/lifts; all functions work by click/tap/keyboard
Labels & errorsEvery field has a visible label; errors explain recovery and use role="alert"
Map alternativeEvery pin corresponds to a list item; pins carry text labels
Reduced motionprefers-reduced-motion globally disables animation in tokens/base.css
Colour independenceTrust states pair colour with icon + text; no colour-only meaning
